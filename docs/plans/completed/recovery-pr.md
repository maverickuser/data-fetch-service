# PR 08 — Reconcile interrupted pulls and delivery

Base: `stack/07-delivery`. Branch: `stack/08-recovery`.

An interrupted Pull invocation could leave its execution key owned indefinitely, and interrupted Delivery could lose a 202 receipt or restart its three-attempt budget. This increment adds a scheduled Reconciler Lambda that scans one bounded state page per invocation, repairs durable intents, and fences expired owners. A Pull timeout checks immutable per-job outcomes first: a recorded source failure is terminal even if the Lambda died before committing it. Group-budget expiry has its own `interrupted` result classification and still creates a child. Otherwise the reconciler reserves one immutable child run before transferring the active claim. The original request still resolves to the root run, whose read projection shows the linked child and latest chain status. At most three children are created after the initial execution; deterministic source failures do not enter this chain.

Recovery also republishes a queue claim interrupted before work, finishes an abandoned post-download fingerprint decision, and resumes Delivery from immutable submission and attempt evidence. If `submission.json` was not saved before interruption, the pinned manifest and handoff history recreate it. A started POST is never reused, a durable 202 is committed without another POST, and `Retry-After` remains anchored to the saved finish time.

Local validation: `make check` passes, including race-enabled unit tests at 2749/2890 statements (95.12%), mocked integration, lint, native and Linux arm64 builds, configuration validation, documentation links, and OpenAPI parity. Fault-injection tests cover retry transfer write boundaries, failure-outcome-to-terminal-transition interruptions, four-execution exhaustion, expired claims, post-download decisions, delivery evidence gaps, and cursor progress. Pull-to-recovery tests distinguish actual HTTP 404 from controlled group-budget expiry. No cloud resources or remote PR were created. Terraform scheduling and manual recovery routes are separate later increments.
